Problem

Solution

Move ordering, preconditions, rollback and warnings behind Namespace methods, exactly as Namespace.EnableTailscale already does.

The control seam is a hidden global with eight branch points

tailscale.go:539 tailscale.go:617 validate.go:55 validate.go:126 verify.go:30 status.go:43 command/tailscale.go:107 ui/tailscale_form.go:193

Nothing enumerates them; you find them by grepping. The last two leak the seam into the frontends — both re-implement the same credential suppression.

Problem

  • deletes four binding wrappers

  • shrinks a 45-symbol interface

Mirrors TailscaleDaemon — the one seam in this subsystem that already works, with a fake that routes canned JSON through the production parsers so it cannot drift.

Problem

  • three httptest servers become one fake
  • SaaS-only paths stay CI-testable

Address Form fields by key, not index

Worth exploring in-process

internal/ui/form.go:404,471,508 · tailscale_form.go:17 · settings_form_*.go  |  integration/ui_test.go:60,194,206

Before — tab-order is the interface

Failure mode: submit is rejected silently (submitIfValid just refocuses), the overlay never closes, and the driver's waitUntil burns 3 of the suite's 10 minutes before reporting a timeout.

After — keys, plus a rejection message

f.Field("clientID")
f.Field("clientSecret")
f.Field("mode") ← insert anywhere

Field sets and validation become table tests in internal/ui. form_test.go already drives Form.Update without a live TUI — the shape exists, it just isn't reachable by key.

Problem

Fields are positional ints and rejected submits are invisible from outside, so the integration drivers encode tab counts and fail by timeout instead of assertion.

Solution

Key-addressed fields plus a rejection message. Integration then asserts only that Docker did the thing.

Wins

  • reordering a field stops breaking tests
  • failures are assertions, not timeouts
  • retires an AGENTS.md hazard note

Top recommendation

01 — Give Namespace a workflow spine

The only candidate whose friction has already shipped as divergent behaviour: the TUI skips the public-DNS preflight, never calls Settings.Validate(), discards deploy errors, has no settings rollback, and can only ever destroy data on remove. Five gaps, one missing module.

It needs no new seam and no ADR revisited — Namespace.EnableTailscale is already the model, and its docstring already claims the role: "the full enable lifecycle shared by the CLI and TUI." Funnel, deploy, update and remove never got the same treatment.
