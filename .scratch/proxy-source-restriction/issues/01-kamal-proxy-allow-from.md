# 01 - kamal-proxy: per-service `--allow-from` source restriction

**Problem:** kamal-proxy routes by Host only. Once needs a route to answer
only when the request's source address is inside a set of CIDRs, so Local
and nodes-Tailnet apps stop answering the public IP on a spoofed Host
(ADR-0016).

**Status:** ready-for-human

> *This was generated by AI during triage.*

## Agent Brief

**Category:** enhancement
**Summary:** Add a per-service source allow-list to `kamal-proxy deploy`, on
the maintainer's own kamal-proxy branch, published as
`basecamp/kamal-proxy:once-02`.

**Why human:** External repository (Basecamp's kamal-proxy), maintainer's own
branch and publishing credentials. Not delegable from this repo.

**Current behavior:**
`kamal-proxy deploy <service> --host <h> --target <t>` serves any request
whose Host matches, from any source.

**Desired behavior:**
- `kamal-proxy deploy` accepts a repeatable `--allow-from <CIDR>` flag. When
  at least one CIDR is given, the service answers only requests whose
  connection source address is inside one of them.
- Source is the TCP peer address (`RemoteAddr`), never `X-Forwarded-For` or
  any header a client controls.
- A request from a disallowed source gets exactly the response an unknown
  Host gets today (`404`, same body), so the service's existence is not
  confirmed.
- The allow-list is part of the service's persisted state, survives a
  restart, and is replaced (or cleared, when omitted) by the next `deploy` of
  the same service, like every other per-service option.
- Health checks the proxy itself makes against the target are unaffected.
- No allow-list means today's behaviour, byte for byte.

**Key interfaces:**
- `kamal-proxy deploy` flag set: `--allow-from` (strings, CIDR notation, IPv4
  and IPv6).
- The service options struct that is persisted to the state file and the
  request handler that selects a service by Host.

**Acceptance criteria:**
- [ ] `deploy --allow-from 172.18.0.0/16`: a request from `172.18.0.1` with the
      matching Host is served; the same request from `192.168.1.50` gets the
      unknown-Host `404`.
- [ ] Multiple `--allow-from` values are all honoured.
- [ ] Re-deploying without `--allow-from` clears the restriction.
- [ ] The restriction survives `kamal-proxy` restart (state file round-trip).
- [ ] `X-Forwarded-For: 172.18.0.1` from a public source does not bypass it.
- [ ] Image published as `basecamp/kamal-proxy:once-02` (or the tag Once
      ticket 04 pins), pullable from Docker Hub.

**Out of scope:**
- Any Once-side change (tickets 03, 04).
- A "private"/"internal" semantic flag; the CIDR list is the whole feature.
- Rate limiting, auth, or anything beyond source matching.
