# 04 - Pass `--allow-from` on non-public routes and pin `once-02`

**Problem:** With kamal-proxy `once-02` (ticket 01) able to restrict a
service by source, Once must ask for it on every non-public route and roll
existing installs onto the new image (ticket 03), closing the spoofed-Host
hole for good (ADR-0016). Then the interim copy from ticket 02 flips back.

**Blocked by:** 01 (image on Docker Hub), 03 (roll + re-register).

**Status:** ready-for-agent

## Agent Brief

**Category:** bug
**Summary:** Local and nodes-Tailnet routes are deployed with
`--allow-from <once network subnet(s)>`; Public and Recovery Handoff routes
are not; `proxyImage` is pinned to `once-02`; the Local help copy returns to
"only reachable from this machine".

**Current behavior:**
`Proxy.Deploy` emits `kamal-proxy deploy` with host/tls/health-check options
only. Every route answers any source.

**Desired behavior:**
- `DeployOptions` gains an allow-list of source CIDRs. When non-empty,
  `deployArgs` emits one `--allow-from <CIDR>` per entry.
- The Trusted Source CIDRs are the IPAM subnets of the `once` Docker network
  (all of them, IPv4 and IPv6 if present), read from Docker at registration
  time. Nothing else is added (loopback never appears as a source inside the
  container).
- Callers set the allow-list for: the Local route registration and the
  nodes-topology Tailnet route registration. Callers leave it empty for the
  Public route and the Recovery Handoff route.
- `proxyImage` becomes `basecamp/kamal-proxy:once-02`; ticket 03's roll then
  upgrades existing installs and re-registers their non-public routes with
  the allow-list.
- The exposure help copy for Local returns to "only reachable from this
  machine" and drops the interim comment from ticket 02.
- Docs (README or wherever exposure is documented) gain one sentence: on
  Docker Desktop and rootless Docker the Proxy cannot see real source
  addresses, so Local/Tailnet enforcement degrades to Host routing there.

**Key interfaces:**
- `DeployOptions` (new allow-list field) and `Proxy.deployArgs`.
- The Local and nodes-Tailnet route registration paths (whatever ticket 03
  left as the shared registration step).
- A `Namespace` accessor for the `once` network's subnets (`NetworkInspect`).

**Acceptance criteria:**
- [ ] Unit: `deployArgs` emits `--allow-from` per CIDR when set, nothing when
      empty.
- [ ] Integration: deploy a Local app; `curl -H 'Host: <app>.localhost'
      http://127.0.0.1/` -> 200; the same request against the host's LAN/
      bridge address that is outside the `once` subnet -> 404 (identical to
      an unknown Host).
- [ ] Integration (headscale control seam, `nodes` topology): the tailnet
      route still answers when reached through the TSDProxy node.
- [ ] Public app and Recovery Handoff still answer from a non-`once` source.
- [ ] Existing install on `once-01` is rolled to `once-02` on next Once run
      and its Local app stops answering from outside the subnet.
- [ ] `make lint`, `make test`, `make integration` green (run under
      `flock /tmp/once-integration.lock`).

**Out of scope:**
- Runtime detection of opaque-source platforms.
- A LAN level or any new Exposure value.
- The `services` topology.
